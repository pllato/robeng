## 1. Что это

**MineEnglish** — платформа-школа английского для детей 5–11 лет в виде многопользовательского
voxel-мира (собственный движок на чистом WebGL, «как майнкрафт»). Школа находится в Алматы
(владелец — Платон, pllato.kz). Ученики и преподаватели заходят в общее 3D-лобби, преподаватели
ведут уроки в своих постоянных классах-мирах по стандартной программе из 100 уроков.

**Жёсткое требование собственника:** механику мира (ходьба, камера, строительство) НЕ менять —
пользователи привыкли. Всё новое делать «объектно»: не экраны-меню, а стойки/здания в мире,
к которым подходишь и жмёшь E.

## 3. Запуск и доступы

```bash
# сервер (в своём терминале, живёт пока открыт)
node /Users/platontsay/Projects/mineenglish/server.js
# публичная HTTPS-ссылка (второй терминал; cloudflared установлен через brew)
cloudflared tunnel --url http://localhost:8642
```

- Порт **8642**. Если `EADDRINUSE` — старый процесс жив: `kill $(lsof -t -iTCP:8642 -sTCP:LISTEN)`
- Туннель обязателен для реальных пользователей: **микрофон и распознавание речи работают только
  по HTTPS** (localhost — исключение). Ссылка quick-туннеля меняется при каждом запуске.
  Запланировано (не сделано): именованный CF-туннель с постоянным доменом типа `play.pllato.kz`
  (у владельца есть аккаунт Cloudflare, опыт wrangler/pages).
- Env-переменные сервера: `PORT` (умолч. 8642), `DATA_DIR` (умолч. `./data`), `ADMIN_PIN`.

**Доступы (боевая база `data/db.json` на 10.08.2026):**
- Владелец: логин `admin`. PIN задаётся `ADMIN_PIN` при ПЕРВОМ запуске (если не задавали — `2468`).
  PIN хранится как sha256 с солью `me-salt:`; **смена `ADMIN_PIN` после создания владельца ничего
  не меняет** — код создаёт owner только если его нет. Забыли PIN → удалить объект owner из
  `data/db.json` и перезапустить с нужным `ADMIN_PIN`.
- Активный преподаватель: `Pla`, постоянный класс `FQTX` (PIN знает только пользователь).
- Ученические аккаунты создаются самостоятельно (имя+PIN), токены автовхода в localStorage (`me_token`).
- В базе 1 лид со стойки (телефон родителя) — видны владельцу в панели.

## 4. Как это работает (архитектура)

Один WebSocket на клиента, JSON-сообщения `{t: тип, ...}`. Сервер держит комнаты в памяти,
персистентные (классы, LOBBY) выгружает в db.json при опустении и на каждом изменении блоков.

**Миры:** `LOBBY` (общий, seed 777001) + классы преподавателей (постоянные 4-буквенные коды,
генерятся при активации) + временные гостевые. Мир детерминирован по seed + журнал edits.
Переключение миров без перезагрузки: `switch` → клиент `resetWorld()` + `startWorld(seed,edits,lobby)`.

**Лобби** (строится клиентом детерминированно в `buildLobbyWorld` по данным init.lobby):
площадь из досок, маяки, аллея арок-порталов активных преподавателей (живые теги: ⭐, ученики,
расписание), стойки: 🎟 Аккаунт (вход/регистрация/профиль/аватар), 🚪 Вход по коду,
🎓 Хочу учиться (лид), 🧑‍🏫 Стать преподавателем, доска рейтинга, стенд «Слово дня»
(+1⭐ раз в день), песочница (x≥100 — только там гости могут строить в лобби).
Взаимодействие: подойти + **E** (на телефоне кнопка ✋). Владелец в лобби получает role teacher
(может строить где угодно) и HUD-кнопку «👑 Панель владельца».

**Роли:** guest → student (регистрация) → teacher (заявка = аккаунт со status pending →
владелец активирует в панели, оплата вручную вне системы) → owner.

**Уроки:** урок = JSON (`public/lessons/`), у учителя в панели (клавиша **T**) каталог →
«Начать урок» → процедуры по кнопке «▶ Следующая». 8 процедур (движок `runStage` в клиенте,
учитель — драйвер, ученикам прилетают обычные task/race):
`hello` (фраза-приветствие), `wordhunt` (гонка сбора слов с Pronunciation Gate),
`touchname` (беги к объекту), `listenbuild` (построй N блоков), `saymove` (фраза «Open the door!»
убирает стеклянную дверь), `grammar` (фраза со строгим порядком слов + мост),
`roleplay` (диалог по карточкам, учитель зачитывает вручную кнопками ✔),
`finale` (общая фраза; когда все done — сервер шлёт celebrate).

**Задания (task) видов:** `touch`, `build`, `find`, `say`, `phrase{words,ordered,finale}`, `role`.
Речь: Web Speech API (en-US) + текстовый fallback (prompt). Проверка слов `wordMatch` —
точное слово, не подстрока (pineapple≠apple), множественное число прощается;
фразы `phraseMatch` (ordered = слова по порядку). TTS: speechSynthesis.

**Голос:** WebRTC-меш внутри класса, сигналинг через тот же ws (`rtc`), STUN Google.
Вход в КЛАСС только с разрешённым микрофоном (в лобби не нужен). **Push-to-talk**: говорить =
удерживать **C** (телефон — кнопка 🎤), у говорящего 🔊 у имени; у учителя клик по кнопке
🎤 = «свободный микрофон». Решение собственника: PTT обязателен для всех.

**CRM:** `db.classes[code].students` — визиты/слова/⭐ по ученикам с аккаунтами (гости не в CRM);
панель учителя: список, расписание (textarea → 1-я строка видна на портале в лобби).
Звёзды: +1 задание, +3 победа в гонке, +1 слово дня; пишутся в аккаунт ученика.

**Аватары:** выбор цвета рубашки (тайлы 14,17,18,20,21) в профиле; учитель всегда красный (19).

### Протокол ws (полный список типов)

client→server: `reg, regTeacher, login, auth(token), lead, adminList, activate, blockTeacher,
enter` (учитель в свой класс), `create` (временный класс), `join(code)`, `switch(code)` (между
мирами), `setAvatar, schedule, wordday, lesson(id|null), stage(n), markDone(id), crm,
move, block(x,y,z,id), task, done, words, voice(on), talk(on), race(words|null), rgot(word), rtc(to,data)`

server→client: `authok(token,user), autherr, err(msg), leadok, adminData, scheduleok, worddayok,
init` (id, code, seed, role, shirt, players, edits, task, dones, words, race, lesson, lobby?),
`add, del, move, block, task, done, words, voice, talk, race, rgot, celebrate, lesson, stage,
crmData, rtc`

⚠️ Историческая грабля: тип `block` занят установкой блока — блокировка преподавателя называется
`blockTeacher` (была коллизия, блоки молча пропадали).

## 5. Как тестировать (проверенный порядок)

```bash
# отдельный сервер с изолированной базой — НЕ трогать боевой data/
cd ~/Projects/mineenglish && PORT=8643 DATA_DIR=/tmp/me-test ADMIN_PIN=9999 node server.js
```
- Две вкладки браузера: учитель + ученик. В консоли есть `window.game` со всем нужным:
  `P, code(), ready(), peers, setPaused(v), setDrag(true)` (обзор мышью без pointer lock),
  `checkWord(text)` (симуляция речи), `startLesson(id), runStage(n), raceState(), lessonState(),
  lobbyState(), doInteract(), netBlock(), voiceState()`.
- **Микрофон обязателен для входа в класс** — в тестах патчить ДО клика:
  `navigator.mediaDevices.getUserMedia=async()=>{const ac=new AudioContext();const o=ac.createOscillator();const d=ac.createMediaStreamDestination();o.connect(d);o.start();return d.stream;}`
- Скрытая вкладка = requestAnimationFrame стоит → физика/проксимити не тикают. Вкладка должна
  быть видима (или двигать сюжет скриншотами). WS-сообщения при этом ходят нормально.
- Голос двух вкладок можно проверить фейковым стримом: `voiceState()` → state 'connected'.

## 6. Известные грабли

1. `EADDRINUSE :::8642` — где-то жив старый сервер (частая ситуация у пользователя): убить по lsof.
2. Quick-туннель: URL одноразовый; метрики cloudflared на `127.0.0.1:20241/metrics` — оттуда
   можно достать текущий hostname.
3. `buildHotbar` при скрытой вкладке получал innerWidth=0 → починено clamp'ом; не убирать.
4. Владелец создаётся один раз (см. §3 про PIN).
5. Генератор уроков: артикли a/an уже поправлены; уроки — шаблонные каркасы, первые 10 надо
   довести вручную (бэклог).
6. В лобби гости строят только в песочнице (сервер режет block при x<100) — не «баг».
7. `switch` в комнате, `join` — только вне; клиентский helper `joinByCode` выбирает сам.
8. Речь/TTS требуют user gesture + HTTPS; на телефонах iOS смотреть playsInline у audio.

  сервера пользователем (сказать явно).
