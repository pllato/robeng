# Pixel English — описание проекта для агентов

Этот файл — единственное, что нужно прочитать новому агенту перед первой правкой.
Он описывает продукт, устройство кода, правила работы и грабли, на которые уже наступали.

## 1. Что это за продукт

**Pixel English** — многопользовательский пиксельный мир, в котором дети 5–11 лет
учат английские слова, выращивая их на своём огороде и сражаясь с боссами.

* Заказчик: **Платон**, владелец школы английского **ELC / Robeng**, Алматы.
  Он не программист — все объяснения и вся выдача по работе должны быть на русском,
  без жаргона, с прямым ответом «что сделано и что не работает».
* Живёт по адресу **https://pixel.elc-kids.kz** (netcup VPS 500 G12, Нюрнберг,
  IPv4 89.58.11.76, Debian 13).
* Аудитория — дети. Всё, что видит ребёнок, должно быть крупным, понятным без чтения
  длинных текстов и не требовать точного попадания пальцем.

### Игровая петля

```
киоск: купить семя-слово  →  посадить на грядку  →  подождать 8 с  →  снять 3 плода,
   называя слово голосом  →  сдать урожай в лавку за монеты  →  купить следующее слово
   →  …  посадил достаточно растений → приходит БОСС

тот же куст дальше:  15 мин → 20 мин → 20 мин, и по 2 плода — это уже повторение
разговорная станция:  сказать фразу целиком → заплатят как за четыре плода
```

**Новый материал — быстро, старый — в режиме повторения.** Первый круг любого слова
созревает почти сразу и даёт сразу три плода: за один заход ребёнок проходит новое слово.
Дальше тот же куст зреет 15–20 минут и даёт по два плода — вернуться к нему стоит
на следующий день. Так фарм на одних и тех же плодах перестаёт быть выгоднее новых слов,
а разговорная станция даёт крупные деньги за фразы — это и есть путь к следующему семени.

Ключевая идея: **слово произносится вслух** — распознавание речи и есть основной
игровой ввод. Экономика связана с прогрессом так, чтобы **нельзя было перепрыгнуть
уровень за деньги**: новые семена открываются, когда предыдущие *посажены*.

**Босс — редкое событие, а не часть обычного дня.** Первый приходит, только когда сошлось
всё сразу: круг новичка замкнут (`soldOnce`), на грядках растёт **10 разных растений**
(`bossNeedPlants`, до 20 к поздним боссам), ребёнок возвращался в огород **5 разных дней**
(`bossNeedDays`, считается по `g.days` — дни, когда он сажал или собирал; до 60 к поздним),
и с прошлого боя собран хотя бы один куст. Зато сам бой короткий: **два слова, а если
сказать в первые 3 секунды оглушения — супер-удар ×2 и хватает одного**.

### Бой с боссом

1. Подойти вплотную и **бить киркой** (⛏) — босс вязнет (скорость −65 % на 2,6 с)
   и копит «оглушение».
2. Через `need` ударов он **ослабевает**: замирает, не атакует.
3. Как только он ослаб, **игра начинает слушать сама** — нажимать на босса не нужно,
   плашка краснеет: «🎙 Слушаю — говори!». Сказал слово — плод летит в босса,
   попадает с брызгами и числом урона. Сказал **сразу**, в первые `CRIT_MS`=3 с — урон ×2,
   и первого босса сносит одним словом. Пока лежит, можно бить словом несколько раз.
4. Оглушение проходит, круг повторяется. Первый босс падает за ~3 круга.

Слово издалека по злому боссу — только царапина (`WORD_FAR = 0.025`), отсидеться нельзя.
Проигрыш = минус одно растение с грядки + респаун на своём огороде.
Победа = приз (оружие / артефакт / питомец / монеты).

## 2. Как устроен код

Всего два файла с логикой. Никаких сборщиков, бандлеров и npm-скриптов сборки.

| Файл | Строк | Что внутри |
|---|---|---|
| `server.js` | ~1400 | Node.js + `ws`. Комнаты, аккаунты, вся экономика, боссы, сохранение. |
| `public/index.html` | ~4750 | Весь клиент: воксельный движок на голом WebGL, UI, звук, речь, WebRTC. |
| `public/lessons/*.json` | 101 файл | Уроки: слова, эмодзи, уровень (Starter → A1 → A2 → B1). |

### Сервер

* Запуск: `node server.js`, порт `8642` (`PORT`).
* Данные: `data/db.json`, пишется через 800 мс после изменения и по `SIGINT`.
  **В нём лежат имена детей и телефоны родителей открытым текстом.**
* Один HTTP-эндпоинт кроме статики: **`GET /version`** → `{build, started, pid}`.
  Это главный инструмент диагностики «а тот ли код запущен».
* Протокол — JSON по WebSocket. Типы сообщений (`m.t`):
  `join · switch · move · talk · garden · voice · rtc · login · reg · autoUser ·
   auth · task · done · race · party · lesson · stage · words · wordday · setAvatar ·
   lead · regTeacher · adminList · activate · block · crm · schedule …`
* Всё про огород идёт через `{t:'garden', act:…}`:
  `get · restore · buy · plant · pick · sell · clear · gift · reset ·
   bossHit · bossWord · bossMove · bossFlee · buyWeapon`

**Три мира (комнаты):**

| Код | Что это |
|---|---|
| `GARDEN` | Улица огородов. У каждого ребёнка свой участок с 6 грядками. Сюда попадают сразу при входе. |
| `LOBBY` | Ресепшн школы: аллея преподавателей, стойки, фонтан. Обнесён стеной — выйти нельзя. |
| код класса | Класс преподавателя (урок, гонка слов, задания). |
| случайный 4-буквенный | Групповой мир от зоны сбора (`t:'party'`), `kind:'garden'`, живёт только на занятие. |

**Порталы.** Одинаковая арка (`portalArch`) на улице огородов и на ресепшне. Вход открывает
экран полёта (`openFly`) со списком живых миров — сервер отдаёт его по `{t:'rooms'}`
(`liveRooms`): код, имя класса, идёт ли урок, сколько людей и кто именно.

**Сад привязан к игроку, не к миру.** У аккаунта он в `db.users[id].garden`, у гостя — в
замыкании соединения (`guestGarden`) и цепляется к клиенту в `joinRoom` через параметр
`carry`, до отправки `initPayload`: иначе в новый мир участок уезжает пустым.

### Клиент

* Движок свой: чанки, жадная сетка, процедурный атлас текстур 8×8 тайлов по 16 px
  на канве 128×128. Никаких внешних библиотек.
* **Две шейдерные программы**:
  * `progMain` — мир, шаг вершины 24 байта (`pos3 + uv2 + light1`);
  * `progSkin` — персонажи, боссы, стрелки, шаг 36 байт (`+ tint3`), даёт покраску
    аватаров по вершинам. Красятся «белые» тайлы `T_BODY=35, T_CLOTH=36, T_HAIR=37, T_FACE=38`.
* Индексный буфер `progSkin` рассчитан на `PQUADS*MAXP + PEXTRA = 132*24 + 1100` квадов.
  **Превысишь — часть геометрии просто не нарисуется, без ошибки в консоли.**
* Речь: Web Speech API (`en-US`, `continuous`), синтез — `speechSynthesis`.
* Голос между игроками: WebRTC mesh, **только STUN** (`stun.l.google.com:19302`).
  TURN нет — за строгим NAT связь не поднимется. Это известное ограничение.
* **Фоновая музыка** — `public/music/garden.mp3`, через WebAudio с `GainNode`, громкость по
  умолчанию 14%. Автоматически уходит в тень (12% от своей громкости), пока игра слушает слово,
  говорит сама или рядом слышен сосед. Сервер отдаёт медиа **потоком с поддержкой Range** —
  без 206-ответов Safari на iPhone музыку не играет — и кэширует на неделю.
* **Спутник «Пикси»** (`pixiTick`) — помощник новичка. Ходит рядом, реплики берёт из того же
  `onbNow()`, что и стрелки, поэтому никогда не расходится с подсказкой. Пока его облачко
  видно, строка `#onbLine` скрыта (`html.pixiTalk`), чтобы одно и то же не писалось дважды.
  Уходит сам после 10 разных растений; позванный из меню (`pixiForced`) остаётся до отказа.
* **Голос по расстоянию.** Микрофон открыт всегда (push-to-talk убран). Громкость каждого
  соседа считается от дистанции: до `VOICE_NEAR=6` блоков — 100%, дальше линейно до нуля
  на `voiceR` (по умолчанию 40, настраивается ползунком в меню, хранится в `me_voice_r`).
  Громкостью рулит WebAudio (`MediaStreamSource → GainNode`), а не `audio.volume` —
  **на iPhone громкость `<audio>` менять нельзя**. Сам элемент при этом `muted`,
  но обязан существовать, иначе браузер не проигрывает поток.
* Отладочный доступ из тестов: `window.game` (`ready() · code() · P · getB() ·
  checkWord() · setPaused() · onb() · bossIntro() · bossWeak() · bossTapAt() …`).
  Скрипт исполняется в глобальной области, поэтому из `page.evaluate` видны и
  объявленные `function`, а `let/const` достаются через `eval('имя')`.

### Важные величины (server.js)

```js
const GROW_NEW    = 8000;             // новое слово зреет почти сразу — новый материал идёт быстро
const GROW_REPEAT = [900000, 1200000];// тот же куст дальше: 15 мин, потом 20 — это режим повторения
const WORD_GROW = {};                 // штучная настройка по плодам, ключ «lesson#word» → мс
const WORD_FRUITS = [3, 2, 2];        // плодов на кусте по кругам: первый щедрый, повторение скупое
const PHRASE_PAY = 4;                 // фраза на разговорной станции = цена четырёх плодов
const BED_SLOTS = 8, BEDS_MAX = 12;   // растений на грядке / грядок на участке
const STUN_MS = 12000, SLOW_MS = 2600;
const wordShare = i => Math.max(0.16, 0.6 - i*0.022);   // 2 слова, с супер-ударом — одно
const CRIT_MS = 3000, CRIT_X = 2;     // сказал сразу после оглушения — вдвое сильнее
const bossNeedPlants = i => Math.min(20, 10+i);
const bossNeedDays   = i => Math.min(60, 5+i*2);
const WORD_FAR = 0.025;               // слово издалека по злому боссу — царапина
const BOSSES = […20], WEAPONS = […20], PETS = […20], ARTIFACTS = […20];
```

Семя слова имеет id вида `lesson#word` — например `starter-01#apple`
(регулярка `WSEED = /^([a-z0-9-]{3,24})#([a-z]{2,20})$/`).

## 3. Как запускать и проверять

```bash
node server.js                 # сервер на 8642
node tloop.mjs                 # любой тест: сам ходит по игре в браузере
```

Тесты — Playwright + предустановленный Chromium:
`/opt/pw-browsers/chromium-1194/chrome-linux/chrome` с флагами
`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`.
Мобильные проверки — через `devices['iPhone 13']`.

**Вывод тестов — на русском, строками `  OK  …` и ` FAIL …`.** Это сделано намеренно:
заказчик читает их сам. Не переводить на английский и не заменять на assert-библиотеку.

## 4. Правила работы над проектом

### Разделение труда

* **Здесь** (агент разработки) — игровой мир, механики, экономика, UI, тесты.
* **Кодекс-агент на сервере** — развёртывание и эксплуатация. Ему уходит архив
  `pixel-english.zip` и `DEPLOY-SERVER.md`. Он не правит игровую логику.

### Обязательное

1. **BUILD-штамп.** В `server.js` и `public/index.html` есть константа `BUILD`
   (формат `ГГГГ-ММ-ДД-NN`). При любой выкатке поднимать её **в обоих файлах**
   и сверять через `/version`. Это единственная защита от «выкатили, а работает старое».
2. **Тест на каждую правку.** Не «проверил синтаксис» — а тест, который повторяет
   действия ребёнка и падает, если сломано. В этом проекте уже трижды случалось,
   что правка объявлялась готовой, а на телефоне не работала.
3. **Смотреть скриншот, а не только тесты.** Половина найденных багов вёрстки
   (кнопки за экраном, панель на пол-экрана, невидимая кнопка) тестами не ловилась —
   их видно только на картинке. Делай `page.screenshot` и **смотри её**.
4. **Русский язык** во всех строках интерфейса, комментариях и отчётах.
5. **Отчитываться честно.** Если что-то не сделано или сломано — сказать прямо,
   с выводом теста. Не «переработано», пока не проверено.

### Нельзя

* Коммитить, выкладывать или логировать `data/db.json` — там персональные данные детей.
* Выставлять порт 8642 наружу — только через Caddy на 443.
* Запускать в проде без `PUBLIC=1` (сервер откажется стартовать с дефолтным PIN).
* Логировать номера телефонов.
* Загружать фотографии детей. Аватар «по фотке» берёт только цвета, **на устройстве**.
* Трогать `DEFAULT_ADMIN_PIN` в коде: пароль владельца задаётся `ADMIN_PIN`
  в `/etc/mineenglish.env` (права 600).

## 5. Грабли, на которые уже наступали

Читать обязательно — каждая стоила отдельного разбора.

| Симптом | Причина |
|---|---|
| «Пропали все посаженные семена» у всех игроков | Необработанное исключение в `hintNext()` роняло процесс. Теперь есть `try/catch` вокруг обработчика и `process.on('uncaughtException')`. |
| Гость возвращается — сад пустой | `sanitizeGarden` не переносил новые поля. **Добавил поле в сад — добавь его в `sanitizeGarden` И в ветку `act:'restore'`.** |
| Кнопка на телефоне не показывается | В атрибуте `style` стоял `display:none` — инлайн-стиль сильнее любого CSS без `!important`. |
| Кнопки улетели за экран | Родитель с `transform` становится точкой отсчёта для `position:fixed` детей. Центруй через `left:0;right:0;margin:0 auto`. |
| Стрелки-подсказки исчезли навсегда | Флаг `askOn` ставился при захвате плода и не снимался. |
| Босс не получает урона | Использовал `B.max` вместо `st.max` → `NaN`. |
| Босс под землёй | В меш не передавали базовую высоту `st.y`. |
| Часть геометрии не рисуется | Переполнение `PEXTRA` в индексном буфере. Молча. |
| Ребёнок появляется внутри блока | Декор поставили в точку появления. Смещай `spawnPt` после стройки. |
| `pkill -f "node server.js"` убивает саму сессию | Шаблон совпадает с командой-обёрткой. Используй `ps -eo pid,args \| grep -E "^ *[0-9]+ node server" \| awk '{print $1}' \| xargs -r kill`. |
| Тест «телепортирует» игрока сквозь стену | Присвоение `P.x` минует физику. Двигай через `joyVec`. |
| Плашка боя висит после боя | Классы `fight`/`weak` снимались только внутри живого боя — снимай их и в раннем `return`. |
| Имя не меняется | Имена уникальны: `findByName` отклонит занятое. В тестах бери новое имя на каждый прогон. |
| В тесте не приходит босс | `act:'restore'` игнорируется для вошедших в аккаунт — работает только для гостя. Заготовка сада для боя — `bossgard.mjs` (`restoreBossGarden`). На телефоне зайти гостем можно: сперва `switch` в сад, и только потом ждать `ready()` — тогда `spGo` жать не надо и аккаунт не заводится. |
| Сорвался не тот плод | `checkWord` принимал любое созревшее слово грядки. Если палец держит плод (`holdFruit`), засчитывается только его слово. |
| Плод срывается «сам» | Игра произносит слово вслух, а открытый микрофон слышит её же. `gameTalking()` глушит распознавание на время своей речи. |
| Голос молчит на ресепшне | В лобби `joinVoice()` не вызывался — остаток от схемы «в лобби голос не нужен». Теперь голос везде. |
| Голос молчит у всех | `joinVoice()` выходит сразу, если `micStream` пуст, а `getUserMedia` никто не звал. Микрофон просим на нажатии кнопки входа (`askMicOnEntry`) — браузер разрешает это только на живом жесте. |
| Игроки не видят друг друга в одном мире | `switch` в ту же комнату удалял её из `rooms`, если игрок был последним. Следующий вошедший получал новый экземпляр. |
| Камера смотрит не туда | При `yaw = 0` взгляд направлен в **−z**. |
| «Плод срываю, а денег нет; жму „Сдать всё“ — ничего» | Телефон заснул, браузер закрыл сокет. Мир рисуется дальше, но ни одно нажатие не доходит. Переподключения не было вовсе: `ws.onclose` показывал тост и всё. Теперь плашка `#netOff`, авто-переподключение с `auth` + `switch`, очередь нажатий отдаётся **после** `init`, сердцебиение с обеих сторон. |
| После переподключения сад пустой | Новый сокет — это новый сеанс: `guestGarden` создаётся заново, `authed` пуст. Любое `garden`-действие уходит в чужой пустой сад. Поэтому после обрыва сперва `auth` и `switch`, и только потом накопленные сообщения. |
| Экран полёта ломает старые тесты портала | `doInteract` для портала больше не переключает мир сам — он открывает выбор мира (`#flyList .flyCard[data-go]`). |

## 7. Быстрый старт для нового агента

```bash
node server.js &                       # поднять сервер
node tloop.mjs                         # убедиться, что базовый цикл жив
node tstun.mjs                         # убедиться, что бой жив
# правка → поднять BUILD в обоих файлах → новый тест → скриншот → полный прогон
for t in tloop tfirst tpick tbed tgrow tgate2 tword tbundle tarrow tstun \
         tboss tfight tlose tbag tact tsave tui2 tava tresetboss \
         treset trepeat tguest tvoice tmob taddold tenter tlobby tsame tsplash tthrow tgeo \
         tboss2 tfightui tmic2 tpick2 tmusic tpixi tfly tcarry; do
  echo "== $t"; node $t.mjs 2>&1 | grep -E "^ FAIL |PAGEERROR" ; done
```

Готовый архив для сервера собирается так:

```
pixel-english/
  server.js  package.json  server-setup.sh  deploy.sh  DEPLOY-SERVER.md
  public/index.html  public/lessons/*.json
```

`data/db.json` в архив **не кладём никогда** — на сервере он свой, и `deploy.sh`
не имеет права его перезаписать.
